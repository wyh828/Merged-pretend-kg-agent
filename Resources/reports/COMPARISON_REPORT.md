# 两项目对比分析报告

> 本文保留上游设计和历史结果，未经本机复现；当前进展和本机验证见 [项目入口](../../README.md)。

> 课题：「通过学术论文、专利、新闻等多源数据，构建可动态更新的知识图谱，通过多智能体协同的方式，预测技术发展趋势」
>
> 对比对象：
> - **tech-trend-kg-agents**（`github.com/wyh828/tech-trend-kg-agents`）—— 知识图谱 + 时序 KG 推理路线
> - **pretend-agent**（`github.com/LisaZhao0709/pretend-agent`，项目名「Predictive Agents」）—— 统计动量信号路线
>
> 日期：2026-09-29

---

## 0. 一页结论

两人做的是同一个课题，但走了**两条互补的技术路线**：

| | 我的项目（tech-trend-kg-agents） | 她的项目（pretend-agent） |
|---|---|---|
| **一句话定位** | 把「技术世界」建成一张**可动态更新的知识图谱**，用**时序 KG 推理**预测技术间的新关联 | 把多源**注意力信号**做成**相对份额 + 动量**，用**排序回测**预测下一个变热的技术 |
| **强项** | 知识图谱、跨源实体对齐、时序推理、**严格无泄漏验证** | 信号模型、**排序评估（NDCG/Spearman）**、工程规范、能捕捉拐点 |
| **短板** | 新兴识别失效（p@k=0）、缺排序指标、定向图 copy 未反超 | **完全没有知识图谱**、baseline 早期粗糙、多智能体停留在角色化 |
| **共同短板** | 双方都没有真正实现课题要求的「**多智能体协同**」 | （同上） |

**结论**：两者高度互补——她的**信号模型 + 排序评估**能救我的**新兴识别（p@k=0）**；我的**知识图谱 + 严格验证**能补她的**课题三要素缺失（知识图谱）**。合并后最值得向老师讲的「突破点」，是补上双方都缺的**真正的多智能体协同**。

## 1. 课题与双方定位

课题三要素：**① 多源数据 → ② 动态知识图谱 → ③ 多智能体协同预测**。

| 要素 | 我的项目 | 她的项目 |
|---|---|---|
| ① 多源数据 | ✅ 6 源（含专利、中文新闻） | ⚠️ 5 源（无专利、无中文） |
| ② 动态知识图谱 | ✅ 完整（Neo4j + LLM 抽取 + 实体对齐 + 四元组） | ❌ 无 |
| ③ 多智能体协同 | ⚠️ 角色化编排（hermes-agent + 6 角色 + HITL），非真·多智能体推理 | ⚠️ 4 个薄角色类 + DeepSeek 研报，非真·多智能体推理 |

**两个项目都没真正交付「多智能体协同」**——这一点对老师汇报时必须诚实，也正是合并后的核心待补项。

## 2. 架构对比

### 我的项目：4 层 9 阶段 KG pipeline

```
编排层  hermes-agent(cron/skills/多agent委派) + APScheduler 降级
预测层  ①新兴识别 ②技术间新关联(链接预测) ③指标时序回归 ④S曲线阶段
图谱层  Neo4j 四元组 (s, r, o, t, source)，LLM 抽取 + 三级实体对齐
数据层  OpenAlex / arXiv / USPTO / GDELT / GitHub / RSSHub(中文)
```
9 阶段：`collect → extract → align → build_graph → predict → report → evaluate → notify → visualize`

### 她的项目：3 层 5 阶段信号 pipeline

```
Attempt/  DataCollectionAgent → DataAnalysisAgent(清洗/检测/标准化) → scoring(相对份额+动量)
          → 多周期排序回测(1M/3M) → ReportingAgent(DeepSeek 直连研报)
Data/     Raw → Interim → Processed → Reports（严格分层、只追加不覆盖）
Resources/ 文献/调研/项目综述/笔记
```

### 差异本质

- **我**：以「图」为核心，事实是 `(头, 关系, 尾, 时间, 来源)` 四元组，预测的是**结构**（技术间会不会产生新关联）。
- **她**：以「时序」为核心，观测的是每个技术的**注意力份额时间序列**，预测的是**热度**（谁下一个变热）。

## 4. 关键实测数字（诚实口径）

> 注意：**两边的指标不在同一口径**，不可直接比大小。我的 MRR 是链接预测的排序指标；她的 NDCG/Spearman 是热度榜单的排序指标。对比只能看「各自任务上做得好不好」。

### 我的项目（walk-forward，共现图为主边源）

| 目标 | 指标 | 值 | 判定 |
|---|---|---|---|
| ② 技术间新关联 | TKG filtered MRR | CyGNet **0.9459±0.0765** vs RotatE **0.4487** | ✅ copy 占优，但 `relates_to` 是**无向共现代理**，非真实定向关系 |
| ②（定向图消融） | filtered MRR | CyGNet **0.1621** < RotatE **0.2390** | ❌ 定向稀疏图上 copy 无史可复（86.5% 测试 tail 是全新） |
| ③ 指标时序回归 | RMSE | **0.5269±0.0840**（活动量代理）；引用量口径 **54.85±1.37** | ✅ 可跑，真值仍偏代理 |
| ④ S 曲线阶段 | 阶段分布 | emerging 998 / mature 3965 / declining 37 | ✅ 3 阶段（分层选样修正后） |
| ① 新兴识别 | precision@k | **0.0** | ❌ Kleinberg 检出泛化概念，信号弱 |

### 她的项目（walk-forward，1M/3M 前瞻）

| 指标 | 1 月前瞻 | 3 月前瞻 | 解读 |
|---|---|---|---|
| Top-1 Lift | 1.1251 | **1.1360** | 榜首技术未来活跃度高于市场均值 |
| Spearman ρ | 0.2690 | **0.2762** | 排序单调性弱正相关 |
| NDCG@3 | 0.7614 | **0.7732** | **vs 随机 +134%**，头部命中强 |
| NDCG@5 | 0.7620 | 0.7678 | vs 随机 +92% |

- **拐点捕捉**：LLM 爆发期（2024-02~03）Spearman ρ=0.88、NDCG@3=1.0；量子计算异动（2024-12）ρ=0.76。
- **近期信号衰减**：最近 2 窗口（2025-05/06）ρ 降至 0.10~0.24，提示主题切换期。

## 5. 成果突破清单（合并后向老师可讲的故事）

### 来自我的项目

1. **动态知识图谱 + 跨源实体对齐**：6 源异构数据 → Neo4j 四元组 `(s,r,o,t,source)`，59,423 节点 / 91,303 边，三级实体对齐（强 ID 锚点 → rapidfuzz 字符串匹配 → sha1 兜底），跨源同一技术统一 `entity_id`。
2. **时序知识图谱推理落地**：CyGNet 复制机制 + TLogic 可解释规则 + RotatE 静态对照，共现图上 copy 机制显著占优（0.9459 vs 0.4487），验证了「技术演化高重复性」这一先验。
3. **严格无泄漏验证体系**：walk-forward + purge/embargo + 自动 leak_check，把「用过去预测未来」的公平性做到可审计（`leak_check.json ok=true`）。
4. **端到端自动化 + 可视化**：9 阶段 pipeline + cron 每日增量 + notify 推送 + HITL 审校 + 自包含 SVG 仪表盘。

### 来自她的项目

5. **相对注意力份额模型**：用「份额 + Laplace 平滑」解决「头部成熟技术永远霸榜」的经典问题，是技术预测中「相对化」的正确做法。
6. **排序质量评估体系**：Top-1 Lift / Spearman ρ / NDCG@3/5 多周期回测，NDCG@3 0.76（+134%），能**捕捉 LLM 爆发与量子异动**这种结构性拐点——这是可演示、可说服老师的「效果」。
7. **工程与文档规范**：AGENTS.md 工作协议、SQLite 缓存 + 限速 + 指数退避、配置驱动、版本化实验管理、5 份 87KB 文档——可复现性做到了可直接验收。

## 6. 不足之处清单（对老师诚实）

### 双方共同

1. **「多智能体协同」名不副实（最关键）**：两边都是「角色化编排 + 串行 pipeline」，不是 LLM 多智能体之间的**记忆/反思/辩论/规划**。我的 6 角色是数据类，她的 4 角色是薄抽象（Memory_Design、Reasoning_Architecture 是空目录）。课题三要素里最「前沿」的一环，双方都没真正做。

### 我的项目

2. **目标①新兴识别失效**：precision@k = 0——Kleinberg 突发检出的是「Identification (biology)」这类泛化概念，不是真技术趋势。这是「最接近用户想要的『预测热门方向』」的目标，恰恰是没做好的。
3. **时序 copy 的优势只在「共现代理图」上兑现**：真实定向图（uses/improves）上 CyGNet 0.1621 < RotatE 0.2390，专利引用图直接退化——「CyGNet > RotatE」缺乏一张**真实定向图**的证据。
4. **缺排序类评估指标**：只有 MRR/Hits/MAE，没有 NDCG/Spearman/Top-1 Lift，与「预测热门榜单」这个最终诉求之间隔了一层。
5. **真值偏代理**：回归目标用「月度活动量」代理，真实引用数/star 时序尚未全量接入。

### 她的项目

6. **完全没有知识图谱**：课题三要素之一「动态知识图谱」缺失——没有实体/关系抽取、没有图存储、没有链接预测。她的「预测」本质是时间序列信号分析。
7. **早期 baseline 粗糙**：`technology_cultivation_00` 的 moving_average / linear_regression 对多个主题的 gdelt 预测是**全零**（源数据缺失导致），基线质量不稳定。
8. **数据源与描述有落差**：README/仓库描述列了「专利/新闻/推文/法律/投资」等多源，但实际只接了 CrossRef/OpenAlex/GDELT/GitHub/arXiv 5 个，**无专利、无中文新闻**。
9. **主题粒度偏粗、数量偏少**：仅 5–6 个主题标签，且存在「LLM 学术源 vs 新闻源」同标签重复的问题（报告自述需主题消歧）。

## 8. 附：指标口径说明（避免汇报时被问倒）

- **filtered MRR / Hits@K**：链接预测指标，`(s,r,?)` 猜尾实体，filtered 剔除「同样正确」的干扰。我的任务专用。
- **Top-1 Lift**：榜首技术未来活跃度 / 技术池均值，>1 表示有正向选技术能力。
- **Spearman ρ**：预测排序与真实排序的单调相关性，[-1,1]。
- **NDCG@K**：考虑位置折扣的排序命中质量，@3/@5 关注头部。
- **为何不可比**：我的 0.9459 是「共现代理图上猜关联」的 MRR；她的 0.76 是「热度榜单」的 NDCG。任务不同、图不同、指标不同，**不可直接比大小**，只能说各自任务上是否达标。
